# Issue #206 AI 검색 근거 문서 그룹화 및 가로 넘침 수정 설계

closes #206

## 1. 배경

검색 API는 같은 문서에서 서로 다른 청크를 최대 두 개까지 반환할 수 있다. 기존 화면은 청크마다 문서
카드를 만들기 때문에 하나의 파일이 중복된 것처럼 보였고, 긴 청크 텍스트가 CSS Grid의 최소 너비를
늘려 검색 결과가 화면 밖으로 확장될 수 있었다.

## 2. 성공 기준

- 동일한 `documentId`의 근거 청크를 문서 카드 하나로 묶는다.
- 카드 안에서 원래 인용 번호, 청크 수, 페이지와 발췌문을 유지한다.
- 대표 유사도는 해당 문서 청크 중 가장 높은 점수를 사용한다.
- 인용 목록이 없는 응답도 검색 결과를 같은 규칙으로 그룹화한다.
- 긴 제목과 발췌문이 검색 결과 영역의 가로 폭을 늘리지 않는다.
- 검색 API와 RAG 모델 설정은 변경하지 않는다.

## 3. 화면 처리

`groupSearchSources`가 인용 또는 원시 검색 결과를 처음 등장한 문서 순서대로 그룹화한다. 같은 청크가
반복 인용되면 한 번만 표시하고, 서로 다른 청크는 인용 번호와 발췌문을 모두 카드 안에 보존한다.

검색 결과 Grid는 `minmax(0, 1fr)` 열을 사용하고 카드와 내부 제목 영역에 `min-width: 0`을 적용한다.
카드는 부모 폭을 넘지 않도록 최대 너비와 overflow를 제한하며, 긴 텍스트는 데스크톱에서 말줄임표,
모바일에서 두 줄 말줄임으로 표시한다.

## 4. API 및 오류 처리

API 계약과 오류 응답은 변경하지 않는다. `SearchResponse.results`와 `citations`를 화면 전용 모델로
변환하는 처리만 추가한다.

## 5. 테스트

- 같은 문서의 서로 다른 청크가 카드 하나로 묶이는지 검증
- 같은 청크의 반복 인용이 중복되지 않는지 검증
- 인용이 없는 응답의 검색 결과 그룹화 검증
- 결과 Grid와 카드의 가로 폭 제한 CSS 회귀 검증
- 전체 프론트엔드 빌드, 서버 렌더링 테스트와 lint 실행

## 6. 제외 범위

- 검색 결과 청크 개수와 검색 알고리즘 변경
- RAG 모델 또는 Timeout 변경
- 대화 기록 기능
